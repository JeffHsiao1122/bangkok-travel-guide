# 主要功能驗收與日期撤銷修正

日期：2026-10-23。狀態：已經使用者確認發布，程式版本 61a56e9d9998277ba6646b60705fb99f733f27df；正式驗證見 trip-undo-release.md。

## 已重現並修正的問題

將原創三日行程延長為四日，切到第四天後按「撤銷上次修改」，原本會出現 Cannot read properties of undefined (reading date)，編輯器消失。原因是恢復成三天時，選中的日期索引仍停在第四天。

修正在恢復歷史行程時，同步將選中的日期限制在恢復後的天數內。例如第四天被移除後改顯示第三天。既有活動、來源快照、時間、費用與儲存格式均不改動；未操作使用者原有行程。

手機 390 與電腦 1280 實際重現流程，修正後均通過，並檢查儲存、重新整理、三天的活動資料與修正前保存的原行程一致。

## 本輪驗證

47 項 Node 既有測試全部通過，Pages 建置及資源路徑檢查通過。

新增可重跑的開發驗收腳本 scripts/check-trip-flows.mjs，透過環境變數指定既有 Playwright、瀏覽器與本機預覽，不新增正式網站套件。腳本拒絕對非 localhost／127.0.0.1 網址執行，以免誤操作正式資料；每組使用獨立瀏覽器儲存空間。

六組端到端情境全部通過：

1. 手機延長日期、切換新日期再撤銷、保存與重新整理。
2. 電腦執行相同日期撤銷流程。
3. 四步表單自動排程、必去與排除、預算限制、上／下移、跨天移動與撤銷、時間與備註編輯、鎖定重排、其他天不變、地圖／預算頁與保存。
4. 備份視窗、實際下載 JSON 檔、以檔案選擇介面匯入、建立新識別碼、不覆蓋原行程、錯誤匯入保留資料、複製、刪除及清除的取消／確認、重新整理。
5. 建立空白行程、自訂未知費用活動、縮短日期的取消／確認／撤銷、移除活動與撤銷、草稿重新整理還原，以及正式保存。

## 安全、資料與限制

這一輪只調整編輯器的撤銷狀態，沒有取得外部旅遊資料、銀行資料、照片、評價或授權，也未新增 API、金鑰、費用、帳號及套件。測試網路只允許本機預覽，不點擊第三方連結。刪除與清除只用隔離瀏覽器內自行建立的 QA 合成行程，沒有操作原有使用者資料。

實際下載與檔案選擇匯入，本輪已在獨立 Chrome／Playwright 驗證，補上舊測試報告的這項缺口。PDF 實際輸出、Safari、實體手機觸控、即時道路導航與真實據點營運尚未驗證，不因本輪通過而宣稱全部完成。旅遊內容的未知與授權限制維持原標示。

完整端到端腳本不是 pnpm test 的一部分，需另行啟動已建置本機預覽及使用既有瀏覽器工具；網站使用者不需要安裝 Playwright。本次修正已確認發布並完成針對變更的正式網址驗證，詳見 trip-undo-release.md。
