# 行程列印與 PDF 驗收

日期：2026-10-23。狀態：本機修改與驗證完成，尚未提交、上傳或發布。正式網站仍為日期撤銷修正版。

## 實際找到的問題

先使用現有 Chrome 列印引擎對合成三日行程產生測試 PDF。原本雖有三天，收合的日期提醒與安排理由未輸出，預算只呈現第一天的當日金額；混入空白匯率控制項與固定的跳至主要內容連結。實際 PDF 文字檢查證實第二天的必要提醒遺漏，並非只根據原始碼推測。

## 修改內容

新增只在列印時顯示的 TripPrint 元件，依保存的行程資料產生：

- 每一天的日期、每人活動／交通估算、未知活動費用筆數、旅程合計與未填機票住宿標示。
- 所有天數的活動、抵達／離開時間、停留、費用、備註、交通估算、資料狀態與來源。
- 直接展開顯示的時間／資料提醒、安排理由、整趟備註與未安排的必去項目；不依目前選的日期、地圖或預算畫面決定輸出內容。
- 若活動快照保留餐廳 Wikivoyage 來源，附作者、原始文章／編輯歷史、版本、閱讀日、修改說明與 CC BY-SA 4.0 網址。只輸出既有快照，不讀取外站或回填新資料。
- A4 白底、頁碼、每天另起一頁，允許長備註跨頁，移除導覽、操作按鈕、匯率輸入等介面。

原有螢幕上的每日瀏覽、編輯、JSON 備份與儲存格式保留。沒有加入 PDF 套件或第三方服務，訪客仍使用瀏覽器原生列印功能；PDF 是閱讀副本，不能取代可還原編輯的 JSON。新增忽略 output/pdf/、tmp/pdfs/，防止未來匯出個人行程時誤提交。測試及實際匯出檔不納入 Git。

## 驗證與證據

- 48 項自動測試通過，包括新增的列印完整性、未知費用、提醒、來源署名及不改寫行程回歸測試。
- Pages 建置與資源路徑檢查通過。
- scripts/check-trip-print.mjs 使用既有 Playwright／Chrome，僅允許 localhost／127.0.0.1；每個案例用獨立瀏覽器與合成行程。
- 實際點擊列印按鈕並確認呼叫原生 window.print；另由同一 Chrome 引擎產生實際 PDF，沒有以 HTML 截圖冒充 PDF。
- 三日行程含指南餐廳與未知餐費：5 頁；空白兩日行程：3 頁；十四日行程含 4500 字長備註：17 頁；共 25 頁。
- 以既有 pdfplumber 重新開啟每份 PDF，核對所有日期／活動／每日金額、必要提醒、長備註尾端與完整重複字數、頁碼及紙張內的字元範圍；相關來源署名存在，操作文字已移除，沒有多出空白頁。
- 以既有 Poppler 將最新 25 頁轉成 PNG，逐頁預覽並以原尺寸檢視代表頁；修正網站底色殘留後再產出、轉圖與複查。
- 螢幕／列印樣式可切換，行程儲存原文在列印前後一致，無頁面 JavaScript 錯誤。

程式：scripts/check-trip-print.mjs、scripts/check-trip-print-pdfs.py。原始測試 PDF、逐頁圖與合成樣本在被忽略的 docs/local/pdf-qa；供使用者查看的一份示範在 output/pdf/bangkok-trip-print-sample.pdf（同樣不進 Git）。公開驗證結果為 trip-print-checks.json；代表預覽為 trip-print-preview-summary.png、trip-print-preview-day.png。

首次測試將無座標的空白／自訂行程誤當成應有地圖，已調整為核對實際的無位置資料提示，重跑三份輸出後通過，沒有將不存在的地圖補成虛構座標。

## 資料、隱私與限制

沒有擷取任何新的網站、照片、評價、銀行內容或營運資料，也沒有加入 API、帳號、金鑰、付費服務或執行期套件。開發時使用環境內既有 Chrome、Playwright、pdfplumber 及 Poppler。只輸出原有來源快照與本機合成資料，所有既有資料可信度／授權限制仍適用。

本輪確認 Chrome 列印引擎能產生可讀的真實 PDF，不宣稱已自動操作 macOS 原生另存視窗、選擇使用者存檔位置、實體印表機、Safari 或手機系統分享面板。這些仍需實機操作驗證；CSS 頁碼是否顯示也依瀏覽器支援。PDF 可包含使用者備註，應自行保管；本輪未讀取或上傳私人行程。
